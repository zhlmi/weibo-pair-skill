# Credits 优化策略

本文档定义如何在微博配对的三种模式中优化 API 调用，减少 Credits 消耗。

| 套餐 | Credits | 价格 | 适合场景 |
|------|---------|------|---------|
| FREE | 5次/小时 | 免费 | 仅模式一（自画像），且只能用 weibo-skill |
| BASIC | 3,000/月 | ¥29 | 个人开发测试，日常使用 |
| PLUS | 7,500/月 | ¥69 | 开发 + 频繁使用 + 深度分析 |
| PRO | 32,000/月 | ¥299 | 面向多用户/生产环境 |

## 各模式 Credits 消耗预估

### 模式一：自画像

| 数据源 | 调用次数 | Credits |
|--------|---------|---------|
| weibo-skill status | 1 | 0（免费） |
| weibo-skill interactive-comments | 1 | 0（免费） |
| CLI statuses/mentions | 1 | ~1 |
| CLI comments/to_me | 1 | ~1 |
| **合计** | **4** | **~2** |

**月度使用量（BASIC）**：~1500 次

### 模式二：双人透视

| 数据源 | 调用次数 | Credits |
|--------|---------|---------|
| 我方数据（weibo-skill） | 2 | 0 |
| 找对方 UID | 1 | ~1 |
| 对方微博列表 | 1 | ~1 |
| 对方活跃关注（降级，转发来源零成本） | 1-2 | ~1-2 |
| 互动数据 | 1 | ~1 |
| **合计** | **~6-7** | **~4-6** |

> 对方关注列表改为降级策略后（`friends/other` 不存在），成本反而更低：转发来源从已拉取的微博里提取零额外调用，@账号按每批 ≤50 合并查询，圈子兼容需 1 次 `friends/biz --count 20`（需翻页）。实测整条链路 ~7 次调用 ≈ 5-7 Credits，BASIC（3000/月）绰绰有余。

**月度使用量（BASIC）**：~750 次

### 模式三：关注列表定律

| 深度 | 调用次数 | Credits | 说明 |
|------|---------|---------|------|
| 快扫 | ~5 | ~5 | 只分析关注列表结构 |
| 标准 | ~15 | ~15 | 采样 Top 10 账号微博 |
| 深度 | ~30-50 | ~30-50 | 全量分析 |

**月度使用量（BASIC）**：
- 快扫：~600 次
- 标准：~200 次
- 深度：~60-100 次

## 优化策略

### 1. 默认使用最小数据集

- 模式一默认只用 weibo-skill（免费），CLI 数据作为增强选项
- 模式三默认使用"快扫"深度，用户可要求升级

### 2. 批量请求合并

CLI 的 `users show_batch/other` 支持批量查询（逗号分隔 UID），每批最多 50 个。

```bash
# 不好：50 次单独查询
weibo users show_batch/other --uids 111 --output json
weibo users show_batch/other --uids 222 --output json
...

# 好：1 次批量查询
weibo users show_batch/other --uids 111,222,...,5550 --output json
```

### 3. 会话内缓存

同一目标用户的数据在同一次会话中只查询一次：

```python
cache = {}

def get_user_profile(uid):
    if uid not in cache:
        cache[uid] = call_api(f"users show_batch/other --uids {uid}")
    return cache[uid]
```

### 4. 采样策略

对于模式三（关注列表定律），不需要分析所有关注账号：

| 分析项 | 采样方式 | 说明 |
|--------|---------|------|
| 品类分布 | 全量 | 关注列表本身不消耗额外 Credits |
| 认证类型 | 全量 | 同上 |
| 粉丝量级 | 全量 | 同上 |
| 活跃度 | 全量 | 同上 |
| 情绪倾向 | 采样 Top 10 | 只拉 Top 10 账号的微博 |
| 信息多样性 | 基于品类分布计算 | 不需要额外 API |

### 5. 分析深度控制

在 Skill 中暴露"分析深度"选项，让用户自己选择：

```markdown
请选择分析深度：
- 快扫（~5 Credits）：只看关注了谁，不看发了什么
- 标准（~15 Credits）：采样 Top 10 账号的微博
- 深度（~30-50 Credits）：全量分析
```

### 6. 结果缓存

同一用户的分析结果可以缓存，避免重复计算：

- 相面术结果：缓存 24 小时（微博数据变化不频繁）
- 相亲术结果：缓存 1 小时（互动数据可能变化）
- 关注定律结果：缓存 24 小时

## 月度预算规划

### BASIC（¥29/月，3000 Credits）

| 使用场景 | 频率 | Credits 消耗 | 月度总计 |
|---------|------|------------|---------|
| 自画像 | 每天 1 次 | 2 | 60 |
| 双人透视 | 每周 2 次 | 4 | 32 |
| 关注定律（快扫） | 每周 3 次 | 5 | 60 |
| 关注定律（标准） | 每周 1 次 | 15 | 60 |
| **合计** | | | **212** |

**结论**：BASIC 套餐对于日常使用绰绰有余，还剩 ~2800 Credits 余量。

### PLUS（¥69/月，7500 Credits）

在 BASIC 基础上，可以：
- 每天跑 3 次关注定律标准分析
- 每天跑 5 次双人透视
- 随时使用深度分析

**结论**：PLUS 适合高频使用或需要深度分析的场景。

## 省钱技巧

1. **先跑自画像**：免费，验证 Skill 是否正常工作
2. **关注定律用快扫**：先看一眼，感兴趣再升级到标准
3. **双人透视用缓存**：同一对人不重复分析
4. **避免深度分析**：除非明确需要，标准深度足够
5. **利用 weibo-skill**：自己的数据尽量走 weibo-skill，不消耗 Credits
